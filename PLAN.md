# План реализации игры «Тамагочи» (с простой ASCII-графикой)

## Краткое описание задания

Написать консольную игру тамагочи на C++ с использованием полиморфизма:
- базовый класс (`Pet` / `Animal`);
- минимум 2 наследника (`Cat`, `Dog`);
- минимум одна функция, принимающая указатель на базовый класс, в которую передаётся наследник.

Дополнительно — сделать **несложный UI с ASCII-графикой** прямо в терминале: рамки, полоски-индикаторы характеристик, картинки питомцев и анимации действий из символов. Без внешних библиотек (только стандартная библиотека + ANSI escape-коды для цвета и очистки экрана).

## Идея игры

Пользователь выбирает себе питомца (кота или собаку), даёт ему имя и взаимодействует с ним через меню. Экран постоянно показывает «комнату» питомца: ASCII-рисунок животного, его настроение через смайл-морду, полоски характеристик и подсказки действий. Цель — поддерживать питомца живым и счастливым как можно дольше.

## Что значит «простой UI»

- Экран перерисовывается на каждом ходе (`system("clear")` / `\033[2J\033[H`).
- Окно нарисовано символами рамки: `┌─┐│└┘` или `+-|`.
- Каждая характеристика — полоска вида `HP   [██████████░░░░░░░░░░] 50/100`.
- Питомец — небольшой ASCII-арт (5–7 строк), меняется в зависимости от состояния: весёлый / голодный / сонный / больной / мёртвый.
- Цвет через ANSI-коды: зелёный для «хорошо», жёлтый для «средне», красный для «плохо» (`\033[32m`, `\033[33m`, `\033[31m`, сброс `\033[0m`).
- Анимация действия — 2–3 кадра с короткой паузой (`std::this_thread::sleep_for`), например миска с едой появляется рядом с питомцем.

## Архитектура классов

### Базовый класс `Pet`
Поля:
- `std::string name` — имя;
- `int hp` — здоровье (0..100);
- `int hunger` — голод (0..100, 0 — сыт, 100 — голодает);
- `int thirst` — жажда (0..100);
- `int mood` — настроение (0..100);
- `int energy` — бодрость (0..100);
- `int age` — возраст в «ходах».

Методы (общие, не виртуальные):
- `feed()` — уменьшает голод;
- `drink()` — уменьшает жажду;
- `sleep()` — восстанавливает энергию;
- `play()` — повышает настроение, тратит энергию;
- `tick()` — один ход времени: характеристики ухудшаются;
- `isAlive()` — проверка, жив ли питомец;
- `getMoodState()` — возвращает enum (`Happy`, `Neutral`, `Sad`, `Sick`, `Dead`) — нужно для выбора ASCII-арта.

Виртуальные методы (для полиморфизма):
- `virtual void voice() const = 0;` — звук животного;
- `virtual void specialAction() = 0;` — особое действие, уникальное для вида;
- `virtual std::string species() const = 0;` — название вида;
- `virtual std::string getAsciiArt() const = 0;` — ASCII-рисунок питомца с учётом настроения.

### Наследник `Cat : public Pet`
- `voice()` — «Мяу!»;
- `specialAction()` — `purr()` (мурлыкает, сильно повышает настроение);
- `getAsciiArt()` — несколько вариантов котика (весёлый, грустный, спит, болеет).

Пример арта (счастливый кот):
```
 /\_/\
( ^.^ )
 > ^ <
```

### Наследник `Dog : public Pet`
- `voice()` — «Гав!»;
- `specialAction()` — `walk()` (выгул);
- `getAsciiArt()` — несколько вариантов собаки.

Пример арта (счастливый пёс):
```
  __
 (oo)
 /  \)
*(__)*
```

### Полиморфная функция
```cpp
void renderPet(Pet* pet) {
    std::cout << pet->getAsciiArt() << '\n';
    pet->voice();
}
```
Вызывается из главного цикла отрисовки.

## UI-модуль (отдельный файл `Ui.h/cpp`)

Свободные функции (не методы класса), всё рисование вынесено сюда:
- `clearScreen()` — `std::cout << "\033[2J\033[H";`
- `drawFrame(int w, int h, const std::string& title)` — рамка с заголовком.
- `drawBar(const std::string& label, int value, int max)` — полоска с цветом.
- `drawMenu(const std::vector<std::string>& items)` — пронумерованный список действий.
- `animateAction(const std::string& art, int frames, int ms)` — простая анимация.
- `showMessage(const std::string& msg)` — сообщение внизу экрана.

## Игровой цикл

1. Стартовый экран с логотипом ASCII.
2. Выбор питомца (1 — кот, 2 — собака) с превью обоих артов.
3. Ввод имени.
4. Главный цикл while `pet->isAlive()`:
   - `clearScreen()`;
   - отрисовать рамку, арт питомца, полоски характеристик, меню;
   - ждать ввод;
   - выполнить действие, при необходимости показать анимацию;
   - вызвать `tick()`;
5. После смерти — экран «RIP» с надгробием ASCII и статистикой.

## Меню действий
1. Покормить (анимация миски)
2. Напоить (анимация капель)
3. Поиграть (анимация мячика / прыжков)
4. Уложить спать (анимация «Zzz»)
5. Особое действие (мурлыкать / гулять)
6. Выйти из игры

## Что важно проверить (acceptance criteria)

- Есть базовый класс и минимум 2 наследника.
- Есть функция вида `void f(Pet*)`, в которую передаётся наследник.
- Программа компилируется без предупреждений (`-Wall -Wextra`).
- Нет утечек памяти.
- Экран корректно перерисовывается, рамка не «плывёт».
- ASCII-арт меняется в зависимости от состояния питомца.
- Цвета полосок меняются в зависимости от значения.

## Возможные расширения (если останется время)

- Использовать `ncurses` вместо ANSI-кодов для более стабильного UI.
- Случайные события (питомец заболел — отдельная анимация и действие «лечить»).
- Сохранение/загрузка состояния в файл.
- Третий питомец (например, `Parrot`) — лишний раз показать полиморфизм.
- Звуковые сигналы через `\a`.
